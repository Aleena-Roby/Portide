# Rule: Documentation Standards & Quality Guidelines

## Trigger
Applies when creating, updating, or reviewing documentation files in `docs/` and root README.

## Documentation Guidelines
1. **Concise & High Quality**:
   - Keep documents clean, well-formatted, and dense with accurate technical facts.
   - Do NOT produce bloated, repetitive, or long-winded fluff.
2. **Directory Architecture Alignment**:
   - Place architectural docs in `docs/architecture/`.
   - Place API and security specs in `docs/api/`.
   - Place cloud infrastructure guides in `docs/deployment/`.
   - Place persona walkthroughs and testing runbooks in `docs/user-guides/`.
   - Place database backup notes in `docs/database/`.
3. **Keep Links & References Synchronized**:
   - Ensure `docs/README.md` index links accurately reflect the actual files in `docs/`.
   - Update deployment guides whenever environment variables or service configurations change.
